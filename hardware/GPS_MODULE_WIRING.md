# hardware/GPS_MODULE_WIRING.md — GPS 없는 보드에 GPS 모듈 붙이기 (대체 경로)

> **한 줄 요약**: 레퍼런스 보드(T-A7670G R2 **With GPS**)가 품절이거나 비쌀 때, **"Without GPS" 보드 + 별도 GNSS 모듈**로 같은 기능을 만든다. ★**A7670 모뎀에는 GNSS가 없다** — 그래서 "With GPS" 보드도 사실은 **Quectel L76K 칩을 ESP32 UART에 물려놓은 것**뿐이다. 즉 이 경로는 꼼수가 아니라 **레퍼런스와 같은 구조**다. 단 **전원 게이팅**을 틀리면 전력 예산이 무너진다(§3).

정본 의존: [BOM](BOM.md) · [ELECTRONICS_POWER](ELECTRONICS_POWER.md) · [RELIABILITY](RELIABILITY.md) · [SELF_RIGHTING](SELF_RIGHTING.md) · 펌웨어 [drifter_a7670_cat1](../firmware/drifter_a7670_cat1) · [firmware/README](../firmware/README.md)

★**이 경로는 이 리포에서 아직 벤치 검증되지 않았다**(레퍼런스는 온보드 L76K 변형). 아래는 설계 지침이며, §6 검증을 통과해야 `verified_build`로 인정한다.

---

## 0. 왜 이 문서가 있나 — 판매 옵션 이름의 혼란

LILYGO 판매 페이지의 색상 옵션 `Built-in GPS` / `External GPS` / `Without GPS`는 **무엇이 상자에 들어오는지가 불명확**하다. 실제로 LILYGO 공식 코드 예제는 **온보드 L76K를 다루면서도 이름이 `ExternalGPS_A7670G_Only`**다(모뎀 기준 '외장'이라는 뜻). 따라서:

| 옵션 | 우리 해석 | 대응 |
|---|---|---|
| **Built-in GPS** | L76K가 보드에 납땜됨 | ★**1순위**(레퍼런스). 그대로 쓴다 |
| **External GPS** | ★**불명확** — 커넥터만인지, 모듈이 동봉인지 판매자마다 다를 수 있음 | **구매 전 판매자에게 "L76K 모듈이 상자에 들어오나" 확인.** 확인 안 되면 사지 말 것 |
| **Without GPS** | GPS 전무 | 이 문서의 경로(별도 모듈 배선) |

★**모호함을 피하는 확실한 길**: `Without GPS`를 사고 GNSS 모듈을 **우리가 직접 물린다**. 그러면 상자에 뭐가 오든 상관없다.

## 1. 모듈 선택

| 항목 | 요구 | 비고 |
|---|---|---|
| 인터페이스 | **UART(NMEA 출력)**, 기본 **9600 bps** | L76K·NEO-6M·ATGM336H 모두 해당 |
| 로직 전압 | **3.3 V** | ESP32는 3.3V. 5V 로직 모듈 금지(레벨 시프터 필요) |
| 전원 | **3.3 V 입력**(모듈 자체 레귤레이터 있으면 3.3~5V 허용) | ★§3의 게이팅 레일에서 급전 |
| 안테나 | 세라믹 패치(내장) 또는 액티브 안테나 | ★§4 배치 주의 |
| 소비 | 추적 시 25~45 mA급 | 게이팅 필수 사유 |

권장: **L76K 모듈**(레퍼런스와 동일 칩 = 변수 최소) → 없으면 **ATGM336H** 또는 **NEO-6M**(둘 다 9600·3.3V·NMEA 표준).

## 2. 배선 (T-A7670G R2 기준, 우리 펌웨어 핀맵 그대로)

펌웨어 `drifter_a7670_cat1.ino`가 이미 이 핀으로 정의돼 있어 **핀을 그대로 쓰면 코드 수정이 없다.**

| GPS 모듈 핀 | → ESP32 / 보드 | 펌웨어 상수 | 설명 |
|---|---|---|---|
| **TX** (모듈이 내보냄) | **GPIO 22** | `BOARD_GPS_RX_PIN 22` | ESP32가 NMEA를 **받는** 선 ★가장 중요 |
| **RX** (모듈이 받음) | **GPIO 21** | `BOARD_GPS_TX_PIN 21` | 설정 명령용(안 써도 연결 권장) |
| **VCC** | ★**게이팅되는 3.3 V 레일(V3V)** | `BOARD_POWERON 12`이 제어 | §3 필독 |
| **GND** | GND | — | 공통 접지 |
| (선택) WAKEUP/EN | GPIO 19 | `BOARD_GPS_WAKEUP_PIN 19` | 모듈에 있으면 연결(없으면 미사용) |

- 통신 속도 **9600 bps**(`GPS_BAUDRATE 9600`), 포트 **Serial2**(`SerialGPS`).
- ★**TX↔RX는 교차**한다(모듈 TX → ESP32 RX). 이 한 줄을 뒤집으면 NMEA가 0바이트로 나온다.
- 다른 핀을 쓸 수밖에 없으면 `.ino`의 `BOARD_GPS_RX_PIN` / `BOARD_GPS_TX_PIN`만 고친다.

```
   [GNSS 모듈]                 [T-A7670G R2 / ESP32]
      TX  ──────────────────▶  GPIO 22   (NMEA 수신)
      RX  ◀──────────────────  GPIO 21
     VCC  ◀───── V3V (GPIO 12 = BOARD_POWERON 으로 켜고 꺼지는 레일)
     GND  ─────────────────── GND
  (EN/WAKE) ◀──────────────── GPIO 19  (모듈에 있을 때만)
```

## 3. ★★전원 게이팅 — 여기를 틀리면 프로젝트가 무너진다

GNSS 모듈은 켜져 있는 동안 **25~45 mA**를 먹는다. 딥슬립 중에도 계속 켜져 있으면:

| 급전 방식 | 슬립 소비 | 60분 핑 배터리 수명 |
|---|---|---|
| **게이팅 레일(V3V)** ✅ | 기존과 동일(2~12 mA) | **~6~19일**(정상, ELECTRONICS_POWER §1.5) |
| 상시 3.3V 직결 ❌ | +30 mA 이상 | **~2~3일로 붕괴** |

- **정답**: 보드의 **V3V 레일**에서 딴다. 이 레일은 **GPIO 12(`BOARD_POWERON`)로 켜고 꺼지며**, 온보드 L76K도 원래 여기서 전원을 받는다(펌웨어 README, hole A2). 즉 **레퍼런스와 같은 게이팅을 그대로 물려받는다.**
- V3V 접근점: TF카드 VDD 패드 또는 PX 헤더 16번 핀(펌웨어 README의 프로브 지점과 동일). **확인법**: GPIO12 LOW에서 0 V, HIGH에서 3.3 V가 나와야 한다.
- ★**USB를 꽂은 채로는 검증되지 않는다** — USB VBUS가 V3V를 살려두어 게이팅이 가려진다. **반드시 배터리만으로** 측정.
- V3V 용량이 부족하면(모듈이 커서 전압 강하) 별도 **로드스위치(P-ch MOSFET)**를 GPIO로 제어해 급전한다. 상시 급전은 어떤 경우에도 금지.

## 4. 기구 배치 (부력·자기복원·RF에 영향)

1. **★안테나는 위(하늘)로.** 세라믹 패치 안테나는 하늘을 봐야 한다. 이 유닛은 **수평 자세로 고정**되어 뜨므로(SELF_RIGHTING), 모듈을 **패치면이 위를 향하게** 고정한다. 옆·아래로 향하면 위성이 안 잡힌다.
2. **★솔라 필름의 '필름-프리 창' 아래에 둔다.** Tier 1.5는 몸통을 필름으로 감되 **위쪽 120° 섹터를 비워** 안테나 경로를 확보한다([TIER1_5](TIER1_5_SOLAR_DRIFTER.md) §1). GPS 패치가 필름 아래로 들어가면 수신이 나빠진다.
3. **질량·CG 재계산**: 모듈+안테나+배선이 대략 **+10~20 g** 늘어난다 → `cad/self_righting.py`의 부품 목록에 추가해 **GM > 0**을 재확인하고, 폼도 [RELIABILITY](RELIABILITY.md)·[TIER1_5](TIER1_5_SOLAR_DRIFTER.md) §5 계수로 재산정한다. **밸러스트 40 g은 불변**(상쇄로 줄이지 말 것).
4. **배선 고정**: 진동·표류로 선이 흔들리면 납땜부가 끊긴다. 케이블타이·에폭시로 스트레인 릴리프.

## 5. 펌웨어 (수정 최소)

- 핀을 §2대로 쓰면 **코드 수정 없음**.
- ★**데이터 정직성**: 스키마의 `gnss_source` 필드가 현재 `"l76k"`로 하드코딩돼 있다([schema](../data/schema.md)). **다른 모듈을 쓰면 실제 모델명으로 바꾼다**(예: `"neo6m"`, `"atgm336h"`). 안 바꾸면 데이터가 출처를 거짓말한다.
- 첫 확인은 **원시 NMEA가 들어오는지**부터: 시리얼에 `NMEA chars=`가 0보다 커야 한다(0이면 §2의 TX/RX 교차 또는 §3의 전원부터 의심).

## 6. 검증 (이 경로 전용 추가 항목)

기존 게이트(T1·F2·T4/T7·T6·G5·G6·G7)에 **아래를 더 통과**해야 이 빌드를 쓴다.

| # | 항목 | 합격 기준 |
|---|---|---|
| X1 | **NMEA 수신** | 시리얼에 NMEA 문자 유입 > 0, 문장 파싱 성공 |
| X2 | **야외 콜드 픽스** | 하늘이 트인 곳에서 **3분 이내** 첫 fix(레퍼런스 `GPS_FIX_TIMEOUT_MS` 180 s와 동일 기준) |
| X3 | ★**게이팅 후 슬립 전류** | **배터리만으로** 측정해 GPS 추가 **전과 같은 수준**. +25 mA 이상 늘면 §3 실패 → 방류 금지 |
| X4 | **T1 재통과** | 배선·관통부 추가 상태로 30분 침지, Δm ≤ 0.5 g |
| X5 | **자기복원 재확인** | 추가 질량 반영해 `self_righting.py` PASS + 수조 T4(솔라면 T7) 재통과 |
| X6 | **패치 안테나 방향** | 조립 후 패치면이 위(필름-프리 창 아래)를 향함을 육안 확인 |

## 7. 정직 경계

- 이 경로는 **레퍼런스가 아니다.** 리포의 검증·수치는 온보드 L76K 변형 기준이며, **이 변형은 미검증**이다(§6 통과 전 `verified_build=false`).
- **A7670 모뎀 AT 명령으로 GNSS를 읽으려 하지 말 것**(`AT+CGNSSPWR` 등은 ERROR) — 모뎀에 GNSS가 없다. NMEA는 **모듈의 UART**에서만 온다.
- 절감액(대당 약 2만 원대)은 **납땜점 증가·부피·미검증**이라는 비용과 맞바꾸는 것이다. **첫 검증기는 가능하면 레퍼런스(Built-in) 보드**로 가고, 이 경로는 품절·비용 제약 시의 대안으로 쓴다.
